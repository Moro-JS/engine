# Changelog

One file per release in [`changelog/`](changelog/); the GitHub Release for a
tag carries the same text. Newest first.

- [1.2.5](changelog/v1.2.5.md) — memory under flood on a host with memory to spare, where 1.2.4 was still killed in 11 of HttpArena's 41 resilience attacks. Linux: what the kernel queues for a server's connections to read has a budget (twice the buffer budget, a quarter of the process's memory by default): untouched while the connections fit with the kernel's own receive buffer each, then each connection's buffer is its part, 64 KiB down to 16 KiB, raised again when there is room (a body larger than the buffer from a loopback peer is paced while a thread is that crowded). A thread holding twice its buffer budget closes the connections that are owed responses and take none for half a second, the one owed most first. On a thread over its budget a connection's further requests wait at 16 KiB of untaken responses, not at the write high-water mark. Queued writes are cut to what they hold (they held up to twice it). All 41 attacks survived, highest peak 2.8 GiB of 4; 2,493 engine instructions per keep-alive request against 2,490. `capabilities.socketBudget`, four fields of `probe().bufferBudget`.
- [1.2.4](changelog/v1.2.4.md) — corrections to 1.2.2 and 1.2.3: a pooled request state no longer keeps the buffers a peer grew (a state over 128 KiB is freed; 200 connections left 25 MB behind on 1.2.3, 0.5 MB now); with `http2` on, a reply an engine route had given is no longer dropped when the next line is not HTTP; a request-target that is not origin-form, absolute-form, `CONNECT`'s or `*` for `OPTIONS` is 400 (on HTTP/2 a stream error, as is a `:method` over 64 bytes); `requestTimeoutMs` and `idleTimeoutMs` no longer act up to a sweep interval early; a TLS connection ends with `close_notify`, FIN and the two-second wait a plaintext one has, so a 413 or a `Connection: close` response is no longer lost to a reset when the client is still sending; what all connections hold in buffers together is bounded (`memoryBudget`, an eighth of the memory the process may use unless set: the connection that needs room there is none of gets 503, 1013 or `GOAWAY`, and requests of up to 16 KiB are always served), and on Linux a loop turn has a 50 ms time slice with newly arrived connections served first, so floods that stay within every per-connection limit no longer get the process OOM-killed or keep it from answering (the 41 attacks of HttpArena's resilience suite in a 4 GiB, 2-CPU container: 7 of the 12 that hit 1.2.3 hardest ended in an OOM kill, none does now); `probe().requestStates`, `probe().bufferBudget`, `probe().turns`.
- [1.2.3](changelog/v1.2.3.md) — memory: a connection between requests holds no parser and no request buffers (the connection structure is 480 bytes on Linux, was 1,376; 136 MB less for every 100,000 held keep-alive connections); `trimMemory()` gives back the heap an isolate's start-up left behind; `probe().connections`.
- [1.2.2](changelog/v1.2.2.md) — HTTP/1.1 parsing held to the grammar where it was still lenient (Http11Probe 159/159, h2spec 146/146 on cleartext): a non-ASCII request-target is 400 (`allowNonAsciiTarget` takes it as before), so are an empty `Host`, `*` with a method other than OPTIONS and a malformed chunk extension; a method over 64 bytes is 501; a length no 64-bit number holds is 400, not 413; with `http2` on, first bytes in neither protocol end the connection without a reply.
- [1.2.1](changelog/v1.2.1.md) — `import '@morojs/engine'` no longer costs more memory than `require()`: 5 to 18 MB less resident memory per process on Node.js 20, 22 and 24.11 (the ESM entry loads the loader through `require()`); no other change.
- [1.2.0](changelog/v1.2.0.md) — security and correctness: TLS session resumption no longer skips the client-certificate check; HTTP/2 rapid-reset budget, non-reading peers and flow-control-held responses bounded; `wsBackpressureLimit` holds again (1.1.16 to 1.1.21); uses of freed memory (engine routes changed mid-head, batch buffers, epoll shutdown) and process aborts fixed (pipelined WebSocket handshakes with batch dispatch and `setWsAutoUpgrade`, `wsSend()` on Linux, `close()` in `onWsClose` on libuv, re-entrant response calls); HTTP/1.1, WebSocket and HTTP/2 framing brought in line with the RFCs; `ssl.crl` and `ssl.maxVersion` (`capabilities.tlsCrl`), wrong-typed TLS options throw; Linux glibc binaries load on glibc 2.28 and later; musl and Windows binaries profile-optimised; release candidates under `next`; the BoringSSL roll releases only an unchanged `main`; fewer engine instructions per operation (see the notes). Behaviour changes are listed under "Changes you may notice".
- [1.1.21](changelog/v1.1.21.md) — documentation release: README and roadmap brought up to date; no source change.
- [1.1.20](changelog/v1.1.20.md) — TLS on a bundled BoringSSL (two binaries per ABI; Node's OpenSSL selected by itself under FIPS or an OpenSSL config, or with `MORO_ENGINE_TLS` / `selectTls()`); the bundled copy follows upstream by a scheduled release; `probe().tls`.
- [1.1.19](changelog/v1.1.19.md) — HTTP/2 (ALPN and prior knowledge, the engine's own implementation; h2spec 146/146); TLS replies written straight to the socket, AES-128-GCM preferred by default; request bodies as heap strings or lent buffers (`getBodyType`, `getBodyText`, `getBodyLent`), body buffers pooled per loop; epoll: each ready socket served once per loop turn.
- [1.1.18](changelog/v1.1.18.md) — request bodies collected straight into the body buffer (one copy, half the peak memory of an upload); `getBody()` hands the bytes over without a copy; one callback scope per WebSocket read.
- [1.1.17](changelog/v1.1.17.md) — TLS on the engine's own BIOs (one copy in, one append out, no zeroing); bodies over 8 KiB encrypted from the caller's bytes; ciphertext scratch kept up to 1 MiB.
- [1.1.16](changelog/v1.1.16.md) — `wsSend()` borrows its payload (the backpressure shed is deferred); ASCII text frames as one-byte strings; TLS record buffers released again.
- [1.1.15](changelog/v1.1.15.md) — WebSocket upgrades performed by the engine (`setWsAutoUpgrade`, handshake accessors); frames built in the cork buffer; TLS record buffers kept between records.
- [1.1.14](changelog/v1.1.14.md) — WebSocket replies corked per read (one write for a pipelined batch); one ciphertext buffer per loop on the TLS write path.
- [1.1.13](changelog/v1.1.13.md) — epoll transport: the service order is selectable (grouped, arrival, or measured `auto`); the default is unchanged.
- [1.1.12](changelog/v1.1.12.md) — epoll transport serves each loop turn's sockets grouped by peer CPU.
- [1.1.11](changelog/v1.1.11.md) — epoll transport on one `epoll_wait` per loop turn; engine-answered routes parsed and routed per request.
- [1.1.10](changelog/v1.1.10.md) — engine-answered routes parsed in place and framed from a prepared head; epoll transport the Linux default; request-registry fix.
- [1.1.9](changelog/v1.1.9.md) — parameter routes (`setParamRoute`, `clearParamRoutes`).
