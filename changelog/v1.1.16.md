# @morojs/engine 1.1.16

A WebSocket send-path release, and one 1.1.15 change taken back. No export
or capability flag is added, removed or renamed; nothing on the wire
changes.

## wsSend() borrows the payload

The HTTP response entry points have borrowed their body bytes straight out
of the V8 heap since 1.1.6, under the rule that no binding call may reach
JS while the borrow is alive. `wsSend()` was the one exception: a socket
found past `wsBackpressureLimit` was shed through a synchronous `onWsClose`
from inside the call, so the payload had to be copied first. The shed is now
queued to a later loop turn through the same queue that delivers
`onAborted` and `onWritable` (a `kNotifyWsShed` entry carrying the wsId;
the 1013 Close goes out when it is delivered, unless the socket closed in
the meantime), and `wsSend()` borrows like `respond()` does: an ASCII
string frame costs one copy, into the frame, instead of two. `wsSend()`
still answers `false` at once for a socket it is shedding. Under
`MORO_ENGINE_NOTIFY=sync` the shed stays immediate and the binding copies,
as before.

## ASCII text frames as one-byte strings

A text frame whose payload is pure ASCII (the parser has already validated
it as UTF-8) reaches `onWsMessage` as a one-byte V8 string built straight
from the bytes, skipping the UTF-8 decode; any other text goes through
`NewFromUtf8` as before. Same string either way.

## TLS record buffers released again

1.1.15 stopped setting `SSL_MODE_RELEASE_BUFFERS` to save a malloc/free
pair per reply. Measured on the HttpArena TLS profiles it moved nothing
outside noise, so the mode is back and an idle TLS connection costs ~34 KB
less again.
