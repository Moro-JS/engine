# @morojs/engine 1.2.2

HTTP/1.1 request parsing held to the grammar in the places where it was
still lenient. Each change makes the engine refuse, or answer differently,
a request that no browser or HTTP library sends; together they take the
engine from 147 to 159 of 159 on Http11Probe and from 145 to 146 of 146 on
h2spec against a cleartext listener (the TLS listener was 146 already).
One new serve option, `allowNonAsciiTarget`. No export is added, removed or
renamed.

## Changes you may notice

Each item says who notices and what to do.

- **A request-target with a byte of 0x80 or above is 400** (on HTTP/2, a
  `:path` with one is a stream error). A URI is ASCII (RFC 3986 §2): a
  client that means `é` sends `%C3%A9`, and browsers, curl with `--url`
  escaping, fetch and every HTTP library do. Raw high bytes are also where
  an overlong UTF-8 form of `/` or `.` (`0xC0 0xAF`) gets past a path check
  that runs before decoding. Who: clients that put unencoded UTF-8 in a
  path or query, typically hand-written ones. Do: percent-encode in the
  client, or set `allowNonAsciiTarget: true` to take such targets as before
  (the bytes are handed over undecoded).
- **An empty `Host` value, or a port with no host before it (`Host: :80`),
  is 400** (RFC 9112 §3.2). Who: clients that send `Host:` with nothing
  after it. An HTTP/1.0 request with no `Host` line at all is still served.
- **`GET *`, and `*` with any method but OPTIONS, is 400** (RFC 9112
  §3.2.4). `OPTIONS *` is handed to the application as before.
- **A method token longer than 64 bytes is 501**, as soon as that many
  bytes of it have arrived (RFC 9112 §3). It used to be handed over if the
  line fitted in `maxHeadSize`, and 431 otherwise. The longest registered
  method has 17 bytes.
- **Chunk extensions are held to their grammar** (RFC 9112 §7.1.1): a `;`
  with no name after it, a name or value that is not a token or a
  quoted-string, and whitespace after the chunk size that is not followed by
  a `;` are 400. `5;name=value`, `5 ; name="quoted value"` and several
  extensions on one line are taken as before. Who: nobody known; chunk
  extensions are rare and the ones in use are well-formed.
- **A `Content-Length` or chunk size that no 64-bit length can hold is 400,
  not 413.** `Content-Length: 99999999999999999999` is not a length that is
  too large, it is not a length. The largest value that fits
  (18446744073709551615, `ffffffffffffffff`) is still 413. A
  `Content-Length` with a non-digit in it is 400 wherever the non-digit
  sits; one behind a value already past `maxBodySize` used to be 413.
- **With `http2` on, a cleartext connection whose first bytes are neither
  the HTTP/2 preface nor an HTTP/1 request line is closed without a
  reply.** It used to be sent an HTTP/1.1 400, which an HTTP/2 client reads
  as a malformed frame. A line that is HTTP/1 and wrong (`GET / HTTP/1.9x`)
  is still answered 400 or 505, and so is anything on a connection that has
  already spoken HTTP/1. Servers without `http2` are unchanged.

## Added

- `allowNonAsciiTarget` (serve option, default false): see above.
